# 仕組み

履歴 DB とセッションファイルから何が取れるか，それを木と回にする規則．

## ブラウザの標準機能で足りないこと

Vivaldi を例にする．Chrome や Edge のタブグループも同じ事情．

| 機能 | できること | 足りないこと |
|---|---|---|
| ワークスペース | タブの置き場を分ける | 振り分けは手動か URL のルール頼み |
| ワークスペースのルール | URL の条件で自動振り分け | ドメイン単位．話題や目的では分けられない |
| タブスタック | 2 段までまとめる | 入れ子にできない．木にはならない |
| 関係するタブと共にタブスタック | リンクから開いたタブを親の隣にまとめる | 1 段だけ．検索結果から開くと親が検索結果になる |
| 休止・メモリ節約 | メモリを空ける | タブの数は減らない |

振り分けはブラウザのルールで足りる．木を作る・畳む・放置したタブを棚へ移すのは外で作る．

## 履歴 DB（`History`）

SQLite．ブラウザが開いている間はロックされているので，ファイルごとコピーして読む（`tab-lineage snapshot`）．書き込み途中を写すと壊れていることがあるので，`pragma quick_check` で確かめて取り直す．

- `visits.opener_visit`：新しいタブで開いたときの元の訪問．`visits.from_visit`：同じタブで来たときの元の訪問．親はこの 2 つで決まる．古い DB には `opener_visit` が無い．
- `visits.transition & 0xFF`：0 = link，1 = typed，2 = bookmark，3 = subframe，5 = generated，7 = form，8 = reload．`0x01000000` が立っていれば戻る・進むで来た訪問．
- `visits.visit_duration`（µs）：そのページを開いていた時間．放置の判定に使う．
- 時刻は 1601-01-01 起点の UTC µs．サイトでは実行した環境の地域時間で表示し，夏時間の切り替えがある期間は切り替わる時刻ごとにずれを持たせる．
- `keyword_search_terms`：検索語．ただし POST で検索するエンジン（Startpage など）は検索語が残らず，URL にも出ない．

### 親が記録されない訪問

検索結果から開いたページは，親が記録されていないことが多い．そのままでは根として孤立するので，直前の検索を親として補う（規則 5）．

### ページ内で URL が変わるサイト

地図や SNS のように，読み込み直さずに URL だけ変わるサイトは，遷移が 1 訪問ずつ記録されて長い鎖になる．同じサイト内の遷移は 1 節に畳む（規則 2）．

## セッションファイル（`Sessions/Session_*`）

Chromium の SNSS 形式．先頭 8 バイトはマジックとバージョン．その後のレコードは `uint16 サイズ` + `uint8 コマンド` + 本体．使うのは次の 5 つ．

| コマンド | 意味 | 本体 |
|---|---|---|
| 0 | SetTabWindow | window_id，tab_id |
| 2 | SetTabIndexInWindow | tab_id，タブバーでの位置 |
| 6 | UpdateTabNavigation | pickle：長さ，tab_id，index，url（UTF-8），title（UTF-16） |
| 7 | SelectedNavIndex | tab_id，index |
| 16 | TabClosed | tab_id |

Vivaldi は独自の JSON（`ext_id`，`parent_ext_id` など）も載せる．ワークスペースやタブスタックの所属はここには無い．
ブラウザが使用中の最新ファイルは読めないことがあるので，読めるうち一番新しいものを使う．

## 規則

実行する順．番号はサイトの「規則」の画面と同じ．

1. **つなぐ**：opener，無ければ from を親にする．リロードとサブフレームは節にせず，子をその親へつなぎ直す．
2. **同じサイトを畳む**：同じタブでの同じサイト内の遷移は 1 節にする．新しいタブで開いた場合は題名が同じときだけ畳み，違えばそのサイトに入った最初の節の子として並べる．深さはサイトをまたいだ脱線だけを表す．GitHub のようにリポジトリごとに別物とみなすサイトは `fold_depth` でパスの深さを決める．
3. **戻る・重複をまとめる**：戻る・進むで同じ URL に戻った訪問と，親が同じで URL か題名が同じ兄弟を 1 節にする．
4. **検索を節にする**：検索結果のページは検索語を持つ節として残す．タブとしては，子を開いた時点で役目が終わっている．
5. **検索を親にする**：親の無いリンク訪問は，直前（既定 30 秒以内）の検索の子にする．
6. **回に区切る**：無操作が既定 30 分続いたら区切る．前の回に親がある節は，その回では根として扱い，続きとして記録する．
7. **スレッドに分ける**：同じ回の木を，題名の近さ（日本語は文字 bigram，英数字は単語の TF-IDF の余弦）か入口のサイトが同じかでまとめる．
8. **寄り道を畳む**：木の中で，部分木の話題が残りとほとんど重ならない枝に印を付けて畳む．サイトが変わった所だけを候補にする．
9. **放置に印を付ける**：既定 12 時間以上開いていたページ．今のタブの整理案では，最後に見てから 3 日たったタブを棚へ移す候補にする．
10. **ワークスペースへ振り分ける**：設定の glob で訪問を分類し，回とスレッドには訪問数の多数決で付ける．最多のものが訪問の `ws_share`（既定 1/4）に届かない回は未分類にする．

### 自動ではできないこと

リンクを介さずに別の話題へ移った場合，記録上は親子関係が切れている．話題の近さでスレッドは分けられるが，「何をきっかけに脱線したか」は履歴からは分からない．そこは `labels.toml` のメモで補う．

## 参考にしたもの

- Tree Style Tab（piroor）：ツリーを「外部記憶」「足跡」とみなす考え方．
- Tabs Outliner：閉じたタブも木に残して，保存と開き直しを木の上でやる．
- Chang et al., "When the Tab Comes Due", CHI 2021：タブを開いたままにする理由の調査．
- Tabs.do（UIST 2021）：タブをタスク単位に自動でまとめる．
