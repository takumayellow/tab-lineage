1 枚ずつの行き先

上の例の全部のタブについて，どこへ行くかとその理由．行き先は 3 通りで，ワークスペースに残すか，ブックマークの「あとで読む」へ移すか，閉じるかのどれか．ワークスペースに残すタブは，同じ話題のものをスタックにまとめる．

{{FATES}}
窓タブ行き先理由

「スレッド」は，続けて見たページの木を話題の近さでまとめたもの（系統樹と寄り道）．スレッドの名前は labels.toml で付けたもの．

使い方

コピーした履歴から案を作り，確かめてからブラウザへ戻す．案を作るところまではブラウザに触らない．

  1. snapshot

    使用中のブラウザから履歴（History）と今のタブ（Sessions/Session_*）をコピーする．ブラウザはファイルをロックしているので，解析は必ずコピーに対して行う．

    tab-lineage snapshot data/2026-09-28

  2. build（任意）

    系統樹のサイトを 1 枚の HTML に作って，どこから脱線したかを眺める．サンプルから作ったもの．

    tab-lineage build data/2026-09-28/History.db --session data/2026-09-28/Session_13403000000000000 \
  --config my.toml --labels labels.toml --out site/index.html

  3. arrange

    今のタブを，ワークスペース → スタック → タブと，あとで読むのフォルダの木に分けた案を作り，JSON に書き出す．JSON は手で直してよい（スタックの名前，フォルダ，タブの移動）．サンプルではこう表示される．

    tab-lineage arrange data/2026-09-28/History.db --session data/2026-09-28/Session_13403000000000000 \
  --config my.toml --labels labels.toml --out data/arrange.json
    サンプルの arrange の出力
    {{ARRANGE_OUT}}

  4. apply

    起動中の Vivaldi に案を適用する．まず --dry-run で木だけ確かめる．タブは --close を付けたときだけ閉じる．Vivaldi の起動のしかたは導入．

    tab-lineage apply data/arrange.json --dry-run
tab-lineage apply data/arrange.json --port 9222
tab-lineage apply data/arrange.json --port 9222 --close

ワークスペース

ワークスペースは，1 つのウィンドウの中のタブを用途ごとの置き場に分ける Vivaldi の機能．tab-lineage は設定の [[workspace]] に書いた規則でタブを振り分ける．

  • タブの URL の host/path を，各ワークスペースの match（glob）と上から順に照合し，最初に当たったワークスペースへ入れる．
  • どれにも当たらないタブは「未分類」へ入れる（名前は [arrange] unsorted）．
  • ワークスペースは設定に書いた順に並べ，未分類を最後に置く．絵文字は [arrange] emoji で付ける．
  • apply は同じ名前のワークスペースがあればそこへ入れ，無ければ作る．既存のワークスペースを消したり名前を変えたりはしない．
[[workspace]]
name = "大学"
match = ["lms.univ.example/*", "numpy.org/*", "matplotlib.org/*", "ja.wikipedia.org/*"]

[[workspace]]
name = "個人開発"
match = ["git.example.com/*", "docs.python.org/*", "pypi.org/*", "rich.readthedocs.io/*"]

これから開くリンクは，Vivaldi の設定「ウェブサイトをワークスペースで自動的に開く」でも振り分けられる．ブラウザの規則は新しく開くタブに効き，tab-lineage はすでに溜まったタブを片付ける，という分担になる．

ワークスペースの移り方

並べたあとは，ショートカットキーで行き来してもいいし，ワークスペースごとに別のウィンドウで開いたままにしてもいい．どちらも Vivaldi 8.2 で確かめた操作．

ショートカットで移る
Ctrl+Shift+2〜9 でワークスペース 1〜8 へ切り替える．番号はワークスペースの一覧の並び順．Ctrl+Shift+1 は，どのワークスペースにも入れていないタブへ戻る（「ウィンドウに切り替え」）．Mac でも Control+Shift．
次・前へ順に移る
「次のワークスペース」「前のワークスペース」は既定ではキーが無い．設定 → キーボード でキーを割り当てるか，クイックコマンド（F2 または Ctrl+E）で名前を打って実行する．
一覧から選ぶ
タブバーにあるワークスペースのボタンから一覧を開く．「ワークスペースメニューを表示」にキーを割り当ててもいい．
スクロールで移る
設定の「スクロールでワークスペースを切り替える」を有効にすると，マウスのホイールでワークスペースを順に切り替えられる．
別のウィンドウで開いておく
ワークスペースの一覧でワークスペースを右クリックし，「新しいウィンドウで開く」．たとえば「大学」と「個人開発」を別々のウィンドウに出したまま並べておける．apply はタブを最後に使ったウィンドウへ集めるので，ウィンドウに分けるのは適用したあとにする．

タブスタック

同じワークスペースの中で，同じスレッドに属するタブが {{D_MIN_STACK}} 枚以上あれば，1 つのタブスタックにまとめてスレッドの名前を付ける（Vivaldi の「名前をつけたタブスタック」）．1 枚だけのタブはスタックにせず，そのまま並べる．枚数のしきい値は [arrange] min_stack．

  • スレッド：無操作が {{D_GAP_MINUTES}} 分続くまでの閲覧を 1 回とし，その回の木を題名の近さでまとめたもの．サンプルの昼の回は「窓関数とレポート」「numpy.fft の使い方」「スペクトルの描き方」の 3 つに分かれた．
  • 名前：labels.toml でスレッドに付けた名前．付けていなければ，題名から自動で付けた名前になる．
  • 寄り道：本筋と話題がほとんど重ならない枝は，「寄り道: 〈枝の最初のページ〉」という別のスタックになる．サンプルでは，窓関数を調べる途中でフーリエの伝記から開いたピラミッドの動画より先が寄り道と判定され，旅行やレシピのページと一緒に未分類のワークスペースへまとまった．

スタックにしたあとは Vivaldi の機能がそのまま使える．スタックを選んで「グリッド状にタイル」（Ctrl+F7），「横にタイル」（Ctrl+F8），「縦にタイル」（Ctrl+F9）で中のタブを並べて見られる．使わないスタックは右クリックの「タブスタックを休止」でメモリを空ける．

あとで読む

開いたまま読まなくなったタブは，閉じる前にブックマークバーの「あとで読む」フォルダへ移す．移すのは次の 2 種類．

  • 放置したタブ：最後に見てから {{D_STASH_DAYS}} 日以上たったタブ．日数は履歴の最後の訪問の時刻から数える．サンプルでは 4 日前の夜に開いた記事が当たる．
  • 読みもののワークスペースのタブ：[arrange] reading_workspaces に書いたワークスペースへ振り分けたタブは，新しくても開いたままにせず，あとで読むへ回す．サンプルでは「読みもの」．

フォルダは [[arrange.folder]] の規則で分ける．上から順に照合し，最初に当たったフォルダへ入れる．match は URL の glob，title は題名の正規表現（大文字と小文字を区別しない）．どれにも当たらなければ「あとで読む」の直下に入る．

[arrange]
reading_workspaces = ["読みもの"]

[[arrange.folder]]
path = "開発/Rust"
title = "(?i)rust"

[[arrange.folder]]
path = "開発/Web"
match = ["developer.mozilla.org/*"]

apply は同じ名前のフォルダがあればそこへ足し，同じフォルダに同じ URL のブックマークがあれば足さない．何度適用してもブックマークは増えない．ブックマークへ移したタブは，--close を付けたときだけ閉じる．

閉じるタブ

開き直す必要の無いタブは「開き直さない」として案に載せる．閉じるのは apply に --close を付けたときだけで，付けなければ一覧を表示して残す．

理由判定
検索結果設定の lineage.search に当たる検索結果のページ．調べた先のページは別のタブとして残り，検索語は履歴に残っている．
重複前にあるタブと同じページ．フラグメント（# 以降）と計測用のクエリ（utm_*・fbclid など）だけを無視して比べる．?id=101 と ?id=202 のようにほかのクエリが違えば別のページとして残す．
ログイン・決済など設定の privacy.drop に当たる画面．
ブラウザの画面http(s) と file 以外のタブ（vivaldi://settings など）．

系統樹と寄り道

スタックの元になるスレッドと寄り道は，履歴から作る木で決まる．build で作るサイトでは，その木と回を見られる．サンプルから作ったサイトでは，昼の回にエジプト旅行への寄り道が畳まれている．

画面内容
概観日 × 24 時間の帯に回を並べる．大きい回と名前を付けた回を上に出す．
回の一覧語・ワークスペースで絞り込み，新しい順・大きい順などで並べる．
回スレッドごとのレーンに訪問を時刻で打ち，下に木を出す．寄り道の枝は畳んである．
今のタブ開いているタブをワークスペース → 目的 → タブの木に並べた整理案．
規則木と回を作った規則と，その回の集計．

木と回を作る規則

上から順に適用する．番号はサイトの「規則」の画面と同じ．

  1. つなぐ：新しいタブで開いた元（opener），無ければ同じタブで来た元（from）を親にする．再読み込みとサブフレームは節にしない．
  2. 同じサイトを畳む：同じタブでの同じサイト内の移動は 1 つの節にする．木の深さはサイトをまたいだ移動だけを表す．
  3. 戻る・重複をまとめる：戻る・進むで同じ URL に戻った訪問と，親が同じで URL か題名が同じ兄弟を 1 つの節にする．
  4. 検索を節にする：検索結果のページは検索語を持つ節として残す．語が違えば別の節．
  5. 検索を親にする：親の記録が無いリンクの訪問は，直前 {{D_SEARCH_WINDOW}} 秒以内の検索の子にする．
  6. 回に区切る：無操作が {{D_GAP_MINUTES}} 分続いたら区切る．
  7. スレッドに分ける：同じ回の木を，題名の近さ（日本語は文字の 2-gram，英数字は単語で数えた TF-IDF の余弦）か，入口のサイトが同じかでまとめる．
  8. 寄り道を畳む：サイトが変わった所から先の枝のうち，話題が残りとほとんど重ならないものに印を付けて畳む．
  9. 放置に印を付ける：{{D_STALE_HOURS}} 時間以上開いていたページに印を付ける．
  10. ワークスペースへ振り分ける：訪問を設定の glob で分け，回とスレッドには訪問数の多数決で付ける．最多のワークスペースが訪問の {{D_WS_SHARE}}（ws_share）に届かない回は未分類にする．

名前を付ける

自動の名前はページの題名から取るので，長かったり的外れだったりする．outline で回とスレッドの ID を見て，labels.toml に名前を書く．スレッドに付けた名前は，そのままスタックの名前になる．

tab-lineage outline History.db --config my.toml --labels labels.toml

{{OUTLINE_OUT}}

左端の * は featured（概観で上に出す），- は hide を付けた回．スレッドの ID は，スレッドの最初の木の根になった訪問の ID．

{{LABELS}}

回には title（名前），note（メモ），featured，hide（サイトに出さない）を書ける．

適用するときの安全

apply は普段使っているブラウザに手を入れるので，元に戻せない操作をしない作りにしてある．

  • --dry-run は案の木を表示するだけで，ブラウザに接続しない．
  • 適用の前に，全部のタブの題名と URL を案の隣の <案>.before-<日時>.json に控える．
  • ワークスペースとブックマークは消さない．足すだけ．
  • 開いているタブは開き直さずにそのまま移す．案にあって開いていないページだけ新しく開く．
  • 固定したタブは動かさず，閉じない．
  • タブを閉じるのは --close のときだけ．閉じるのは「開き直さない」タブとブックマークへ移したタブで，案に無いタブ（案を作ったあとに開いたタブなど）には触らず，一覧を表示する．
  • 1 枚のタブや 1 つのスタックで失敗しても止めずに続け，最後にできなかったものを表示する．
  • 適用したあと最初のワークスペースを開き，ほかのワークスペースのタブを休止させてメモリを空ける（--no-hibernate で止める）．
  • 案の JSON は手で直せるので，受け付ける URL は http(s) と file:/// だけにしてある．人から受け取った案は中身を確かめてから適用する．

ポートの扱い　apply は DevTools のポートで Vivaldi に接続する．ポートが開いている間は，この PC のどのプログラムもブラウザを操作でき，Cookie や保存したパスワードも読める．127.0.0.1 だけで待ち受けるように起動し，適用が済んだらフラグを付けずに起動し直す．

設定

設定は TOML で，--config で渡したファイルを既定値に重ねる（表は項目ごとに上書きする）．全項目と既定値はリポジトリの src/tab_lineage/data/default.toml．

項目意味既定
[[workspace]]name と match（host/path の glob の並び）．書いた順にワークスペースを並べる．なし
[arrange] reading_workspacesタブをあとで読むへ回すワークスペース．[]
[arrange] reading_rootブックマークバーに作るフォルダの名前．"{{D_READING_ROOT}}"
[[arrange.folder]]path・match・title．あとで読むの中のフォルダ分け．なし
[arrange] emojiワークスペースの絵文字．{}
[arrange] unsortedどこにも当たらないタブのワークスペース．"{{D_UNSORTED}}"
[arrange] min_stackスタックにする枚数．{{D_MIN_STACK}}
[episodes] gap_minutes回を区切る無操作の分数．{{D_GAP_MINUTES}}
[episodes] timezone回の ID と時刻の時間帯（"UTC"・"+09:00"・"Asia/Tokyo"）．実行した環境
[lineage] search検索結果のページの glob．主な検索エンジン
[threads] detour_theta寄り道とみなす話題の重なりのしきい値．{{D_DETOUR_THETA}}

プライバシー

扱うのは閲覧履歴そのもの．build のサイトは公開することもあるので，既定でも次のものは載せない．

  • URL のクエリとフラグメント（検索語やセッション ID が入りやすい）．keep_query = true で残す．
  • パスに入ったトークン・文書 ID・共有リンクの ID・メールアドレス．長い英数字の区切りを … に置き換える．
  • ログイン・決済の画面（privacy.drop）．訪問ごと消し，子は親につなぎ直す．
  • メール・DM・地図（privacy.mask）．題名とパスを伏せ，「メール」のような名前だけ残す．地図は店や住所から住んでいる場所が分かるので既定で伏せる．
  • 中身の無い中継画面（privacy.drop_titles）．
  • メールアドレス・電話番号らしい数字の並び・URL を含む検索語と，長すぎる検索語（privacy.drop_terms で足せる）．
  • ローカルファイルのパス．ファイル名だけ残す．

一方，arrange の JSON と apply の控えは自分のブラウザへ戻すためのものなので，実際の URL と題名がそのまま入る．リポジトリやサイトに載せない．生の History とセッションファイルも同じ．どれも外部へは送らない．

このページの例は，すべて架空のサンプル（examples/sample/make_sample.py）から作った．

導入とコマンド

Python 3.11 以上．依存パッケージは Windows の tzdata（時間帯の表）だけで，apply は websocket-client も使う．

pip install "tab-lineage[apply] @ git+https://github.com/takumayellow/tab-lineage"
コマンドすること
snapshot使用中のブラウザから History とセッションをコピーする．--browser は vivaldi・chrome・edge・brave．
outline回とスレッドの一覧と ID を表示する．
build系統樹のサイト（1 枚の HTML）を作る．
arrange今のタブの整理案を作る．
apply整理案を起動中の Vivaldi に適用する．
stats木と回の集計を表示する．
tabsセッションファイルのタブを並び順に表示する．

apply の前に，DevTools のポートを開けて Vivaldi を起動する．Chromium 136 以降，既定のユーザーデータのフォルダではこのフラグが無視されるので，--user-data-dir で別のフォルダを指定する．

vivaldi --remote-debugging-port=9222 --remote-debugging-address=127.0.0.1 --user-data-dir=<フォルダ>

制約

  • apply は Vivaldi だけ．ワークスペースとタブスタックが Vivaldi の機能なので．系統樹のサイトと整理案は Chrome・Edge・Brave の履歴からも作れる．
  • apply は DevTools のポートを開けて起動したブラウザにしか適用できない．Chromium 136 以降は既定のユーザーデータのフォルダで開けられない．
  • ワークスペースの作成と切り替えは，Vivaldi の画面の内部の関数を探して呼ぶ．版が変わって見つからないときは，ワークスペースを手で作っておけば名前で照合して続ける．
  • 前に作ったスタックに適用し直すと，名前は付け直すが，同じスタックに入っている「あとで読む」行き・閉じる側のタブ（--close を付けないとき）と案に無いタブはスタックから出さない（#3）．
  • リンクを介さずに別の話題へ移った場合，履歴では親子がつながらない．寄り道は話題の重なりで判定するので，言語の違うページが混ざった枝は寄り道と判定されやすい．外れたら JSON を手で直す．
  • POST で検索するエンジン（Startpage など）は検索語が履歴に残らない．
  • ブラウザが書き込み中の最新のセッションファイルは読めないことがあり，そのときは読めるうち一番新しいものを使う．
